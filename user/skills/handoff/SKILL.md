# 工作交接

生成供后续 Agent 或未来会话使用的交接产物。交接是当前状态的快照，不是继续实施的授权，也不迁移会话文件、Git 状态或 Codex 任务。

会话 JSONL 的跨机器迁移使用 `codex-handoff`，不要使用本 Skill。

## 原则

- 以可观察的当前状态为准，不以对话记忆或先前总结替代检查。
- 明确区分已验证事实、用户陈述和推断；只记录实际执行过的验证。
- 保留重新发现成本高的决定、理由和精确恢复信息。
- 不复制密钥、令牌、密码或其他凭据；不要粘贴完整对话或大段 diff。
- 不得仅为生成交接而修改、提交、暂存、重置、清理、推送、部署或改变工作状态。

## 处理方式

1. 从当前任务和 `$ARGUMENTS` 确定范围。参数指定子系统、文件、Issue 或目标时聚焦该范围；否则覆盖当前活跃工作。只有范围不明会造成误导时才提问。
2. 在总结前检查真实状态：读取适用的 `AGENTS.md` 等工作区规则，检查相关文件、产物、工具输出和可访问的外部状态。无法访问的状态要如实标注“未检查”及原因。
3. 若处于 Git 仓库，按任务相关性检查仓库根目录、分支、HEAD、工作区是否脏、相关已修改或未跟踪文件、变更概要和近期提交。优先使用 `git status --short --branch`、`git diff --stat`、`git diff --name-only`；仅在需要理解任务时读取针对性的 diff，避免输出大段原始 diff。
4. 记录验证状态：列出实际执行的命令或检查及结果；明确重要但未执行的检查。没有当前会话证据或可检查产物时，不得把他人的“已通过”表述为已验证。
5. 记录会约束后续工作的决定及原因。仅在避免重复踩坑时记录被拒绝方案。保留恢复所需的路径、标识符、分支、命令、端口、版本和接口信息；路径跨机器可能失效时，同时提供仓库相对路径。
6. 单独检查并记录并行 Agent、后台进程和外部操作：其状态、标识符、最新已知结果及仍待确认项。不要声称已停止或完成未实际确认的任务。
7. 区分已知问题、不确定性、风险、待办与阻塞项。不要为了使交接显得完整而编造解决方案。
8. 除非用户明确要求保存，直接在回复中给出交接内容，不创建文件。

## 输出格式

省略确实不适用的章节；非代码工作以相应的来源状态替代 Git 信息。

```markdown
# 工作交接

> 快照时间：<时区和时间>。后续状态可能已变化。

## 目标
用一小段说明预期结果和本次交接范围。

## 当前状态
- 已完成或当前可用的内容。
- 部分完成、未开始、阻塞或未检查的内容。
- 脏工作区、未保存产物或其他重要状态。

## 变更与产物
- 重要文件、组件、文档、数据或配置，以及其作用。
- 指向真实来源，不粘贴大段内容。

## 决定
- 重要选择、理由及值得避免重复尝试的方案。

## 验证
- **实际执行：** 命令或检查及结果。
- **未验证：** 仍需执行的重要检查。
- **已知限制：** 覆盖缺口、环境约束、警告或假设。

## 并行与外部状态
- 正在运行、等待中或已完成的 Agent、后台任务和外部操作；包含可恢复的标识符。
- 无法检查的外部状态及原因。

## 未解决问题与风险
- 剩余缺陷、不确定性、阻塞项或兼容性风险。
- 推断必须标注为“推断”。

## 下一步
1. 可立即执行且价值最高的一步。
2. 随后的具体步骤。

## 恢复上下文
- 工作目录、仓库、分支和 HEAD。
- 重要入口文件、服务、进程、端口、环境、数据集或外部依赖。
- 精确的恢复、运行或验证命令；相关 Issue、PR 或任务标识。
- 来源状态所在位置。

## 给后续 Agent 的备注
只保留容易遗漏的警告或上下文。
```

返回前确认：后续 Agent 能否看懂目标和实际状态、区分验证与假设、定位产物、立即执行第一步，并且交接中没有凭据或不必要的对话历史。任一项不满足时，先修正交接内容。

$ARGUMENTS
