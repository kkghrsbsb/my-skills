# 行为验收场景

这些场景用于审阅和真实试用，不是已执行的测试报告。

| 场景 | 请求与条件 | 应观察到的行为 |
| --- | --- | --- |
| 开始前摸底 | 「我刚接触这个方向，不知道自己懂多少。」 | `research-orient` 先问少量开放问题，了解研究者对基本对象和方法的现有解释与把握，再选择讲解深度；不把摸底当作考试成绩。 |
| 研究中看不懂 | 「你说这个实验支持结论，可我看不懂。」 | 立刻定位缺失的概念或因果环节，用证据解释，并邀请用户复述；不等到下次恢复才处理。 |
| 理解与核实不同 | Agent 已读原始实验，用户只说「看过了」 | 记录实验的核验状态，但用户理解仍为未复述；只有用户真实的复述和自述把握才进入理解记录。 |
| 久未继续的主题 | 「只用项目里已有资料告诉我现在知道什么。」存在旧摘要 | `research-resume` 只读核对旧摘要与真实资料，交付证据边界与理解缺口，不自动建立认识文件或联网搜索。 |
| 单篇来源阅读 | 「读这篇论文，提取与延迟有关的结论。」 | `research-capture` 给出作者、日期、定位、上下文和局限；推断与论文原话分开。 |
| 网页只提供摘要 | 链接不可访问或只有搜索片段 | 明确未读原文，不把片段改写成带伪引文的事实；提出可验证的下一步。 |
| 来源冲突 | 官方说明和使用者访谈得出不同适用条件 | `research-synthesize` 比较各自范围、时间与角色，保留冲突，不静默选一方。 |
| 分支阅读 | 用户手动开空白会话或 fork，选择工作区后研究 API 文档 | 会话按给定问题回报可定位证据和缺口；主会话核对后整合认识，不维持固定会话树。 |
| 研究与决定不同 | 证据支持两个方案，用户选择成本更低的一项 | 记录这是一项 `decision`，不误称来源已经证明它最佳。 |
| 恢复资料整理 | `understanding.md` 说某来源已读，但来源卡没有定位 | `research-resume` 标为未核实，保留笔记并要求核对，不重复假装完成；用短题了解用户现在能否解释关键结论。 |
| Zotero 元数据连接 | 用户要把本机 Zotero 用作研究资料入口并记录连接经验 | `research-tool-connect` 先读已有说明，再只读验证 API 和一条元数据查询，记录实际日期、环境、结果与未验证能力；不把元数据当作论文全文。 |
| 复制工具记录 | 研究项目把 `tools/zotero.md` 带回模板仓库 | 审阅并合并可复用步骤，去掉私人路径和文献清单；旧记录不能代替新环境的连接检查。 |
| 交付状态 | 用户要求「起草建议」，没有要求发布 | 草稿完成即可交付；不默认写入外部知识库、生成引用库、发布或宣称已采纳。 |
