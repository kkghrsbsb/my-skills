# research-doc-flow

让一个主会话持续维护研究问题、证据边界和下一步，并按需要把资料探索、阅读摘录或专题分析交给分支会话。适合个人学习、项目资料整理、技术调研、论文/报告准备，以及隔很久回到一个研究主题时的认知恢复。

它不要求 mdBook、特定笔记软件、Zotero、联网检索、脚本或指定模型。普通 Markdown 是共享接口；已有的文档目录、引用管理器和写作工具可以继续作为项目自己的实现选择。

## 接入项目

将 `.agents/skills/research-*` 和 `.agents/research-flow/` 一起加入目标项目，保持相对位置。共享协议和模板是技能的一部分，不能只复制一个 `SKILL.md`。已有同名 skill、`AGENTS.md` 或 `CLAUDE.md` 时，先比较并只合并适用入口；不要递归覆盖 `.agents`、项目指令或项目 README。

首次需要持久化研究状态时，主会话可参考 [state.example.md](.agents/research-flow/state.example.md) 创建 `.agents/research-flow/state.md`。它是可恢复的工作台，不是事实来源、聊天记录或文献数据库。真实来源、原文、可访问链接、文件定位和你的确认优先于其中的旧摘要。

是否追踪 `state.md`、来源卡片和研究产物由目标项目决定；本模板不修改 `.gitignore`，也不把个人会话链接或本机私有路径写进共享文件。

## 四个入口

| Skill | 适合什么时候用 | 结果 |
| --- | --- | --- |
| [research-orient](.agents/skills/research-orient/SKILL.md) | 新主题、久未继续、资料库不熟悉 | 研究问题、已有资料地图、缺口与下一步 |
| [research-capture](.agents/skills/research-capture/SKILL.md) | 阅读网页、论文、项目文档、数据说明 | 可定位的来源卡和证据摘录 |
| [research-synthesize](.agents/skills/research-synthesize/SKILL.md) | 要比较资料、形成判断、起草文档 | 证据边界清楚的提纲、结论或文稿 |
| [research-resume](.agents/skills/research-resume/SKILL.md) | 中断、换会话、接手资料整理 | 当前事实、未完成问题与恢复路径 |

不必按顺序使用。一个明确的问题可以从 `research-capture` 开始；需要快速解释已有材料时可直接综合；只有在资料和问题都不清楚时才先做定向。

## 工作模型

主会话管理研究问题、范围、资料清单、待验证主张和最终取舍。分支会话只处理被分配的来源集合或子问题，交回带定位的证据和不确定性，不自行改写共享状态或把推断升级为结论。

| 活动 | 关注点 |
| --- | --- |
| `orient` | 明确问题、读者、时限、已有材料和缺口 |
| `collect` | 发现、筛选或取得候选来源 |
| `capture` | 记录来源内容、定位、上下文与可信度限制 |
| `analyze` | 比较来源、检验冲突、形成暂定推断 |
| `synthesize` | 按受众组织答案、笔记、报告或文档 |
| `review` | 检查可追溯性、范围、引用与未证实断言 |

`source claim`、`analysis` 和 `decision` 必须分开：来源实际说了什么；我们据此怎样推断；用户最终决定采用什么。任何一层都不能替另一层背书。没有来源或定位的外部事实应标为待核实，而不是补成看似可靠的引文。

## 保存与分支会话

主会话在研究方向确定、来源批次完成、关键冲突出现、综合完成或暂停时更新工作台；不逐条记录阅读过程。较大的来源阅读可用[来源卡](.agents/research-flow/templates/source.md)，跨来源写作可用[综合模板](.agents/research-flow/templates/synthesis.md)。小任务直接在聊天中交接即可。

当一个子问题范围明确时，可开分支会话：按来源簇、时间段、观点或文稿章节分工，而不是随意按文件切分。分支回报需要包括读过什么、哪些主张有定位、哪些资料相互冲突、哪些内容没有验证。聊天分支不自动等于 Git 分支、独立工作区或已完成的研究。

联网检索、下载资料、安装工具、写入笔记库、创建引用库、发布文稿和删除素材都取决于当前请求与可用权限。本模板不会假定其中任何能力已经存在，也不会把阅读来源的许可扩展为大段复制或公开再发布。

## 一次使用示例

1. 你说「我很久没看这个主题了，先利用现有资料告诉我现在知道什么。」主会话用 `research-orient`，只读整理问题、资料和未知项。
2. 你确定「比较三种方案的适用条件」。主会话按方案或来源集分配 `research-capture`，要求每个结论都有页码、章节、段落或稳定链接定位。
3. 分支会话回报证据与冲突。主会话用 `research-synthesize` 形成比较表、结论与仍需确认的假设。
4. 之后在新会话继续，`research-resume` 对照工作台、真实资料和最终文稿，先核实旧摘要再继续。

## 验证

见 [行为场景](references/scenarios.md)。它们是模板的使用验收，不是已运行的测试。第一次试用建议选择一个小而真实的主题，走完「定向、两三个来源卡、一次综合、一次恢复」，再决定是否添加针对论文、竞品、技术选型或长期知识库的细分入口。
